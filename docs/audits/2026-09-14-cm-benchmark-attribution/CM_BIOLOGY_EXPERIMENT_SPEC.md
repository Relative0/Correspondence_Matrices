# Prepared CM biology experiment specification

Status: implementation-ready experimental design, **not a measured CM performance result**. The local fixed-point control implementation and results in this directory establish the semantic foundation. The matched CM/raw BNet session runner and its lifecycle instrumentation remain the next implementation task. No cloud execution is authorized or proposed.

## Population, units and admission

Use every one of the 22 validated closed models in `BIOLOGY_CORPUS_AUDIT.json`, spanning 5–183 declared targets and whole-model maximum update-function support 2–20. Preserve the explicit target basis, original input bytes and SHA-256. Report target count, function support histogram, maximum support including the target in each equality constraint, induced/elimination width, packed live-component width, CNF auxiliary count, and family cluster separately. Maximum local function width is not a bound on joint fixed-point enumeration complexity.

The 22 models occupy 20 conservative ancestry clusters. Use the audit's size strata (up to 10, 11–20, 21–50, 51+) and support strata (up to 3, 4–8, 9+) without removing empty/sparse cells. Include every model/arm in the ledger; unsupported exponential-width cases are explicit outcomes, not silent omissions. The scalar oracle initially caps full state width at 16, explicit packed materialization at 20, mask payload at 64 MiB, and worker process-tree memory at 1 GiB. Check all allocation limits before construction. More efficient exact backends may admit larger models under the same outer session deadline.

The proposed corpus split is 7 train, 12 development and 3 heldout-candidate closed models. It is not pristine heldout evidence: prior selection, corpus inspection and this correctness audit are disclosed. The three candidate models (074, 210, 211) and their whole families may support an explicitly labeled internal validation after freezing code; they cannot establish broad independent biological generalization. Do not tune on their diagnostic timings. A confirmatory gate needs independently sourced and provenance-validated families, frozen before performance inspection. Treat source annotations/publications as the authority for biological independence, not filenames alone.

The 190 free-input exports stay outside the closed track. Their export-level free-input intent is established, but individual biological roles and translation fidelity remain unresolved. Admit an open model only in a separately versioned track that specifies external assignments, original input domain, and whether counting joint input/state pairs or projected internal states. Never silently add identity equations, clamp defaults or merge differently cased names.

## Exact task and perturbations

The unperturbed task is to count full assignments satisfying every `x_i = f_i(x)`. A witness is a full target assignment checked by evaluating the original parsed functions, independent of the backend encoding. Zero must agree with UNSAT. Count-only backends may use a named companion SAT witness provider; label its provenance and charge its time/memory in the full exact-output session, while also reporting count-only cost separately.

Primary perturbations are **clamps**: replace each selected target's equation with its fixed Boolean value, leaving the other equations unchanged. Secondary conditions retain every original equation and additionally restrict selected targets. These are different scientific questions. For `a = !a`, clamping a to 1 yields one fixed point; conditioning a to 1 yields none. The new control tests enforce this distinction. A plan's `.count(fixed)` method conditions an existing formula: it does **not** implement equation replacement. Implement clamps by retaining per-equation roots and selecting the unclamped equality roots plus clamp units, or by explicit guarded equation selectors whose values are fixed for every query and excluded from the biological state count. Never count free selector choices.

`QUERY_SCHEDULES.json` freezes one ordered 64-query schedule per input before performance timing. Use baseline `{}` followed by deterministic SHA-256 proposals in round-robin single-, double- and triple-target cardinalities; skip duplicate assignments. Input SHA and seed `cm-biology-clamp-session-v1-20260914` define the order; q1, q8 and q64 are prefixes. `prepare_query_schedules.py` supplies the exact algorithm, target/value maps and canonical-JSON schedule hashes. Retain repeated biological outcomes; do not select perturbations because a backend solves them quickly. Schedules are computational perturbations, not claims of experimentally realizable interventions. The schedules have been generated, not executed as performance sessions.

## Required arms and concrete implementation seams

| Arm | Construction and reusable state | Attribution role |
|---|---|---|
| `bnet_scalar_oracle` | `cmbench.biology_controls.bnet_scalar_oracle`; bounded exhaustive states, independent expression evaluator | correctness/comparator |
| `raw_factorized` | Raw BNet AST to `FlatProgram`, equality roots and conjunction; `FactorizedCountPlan(program, names, cache=...)`; cache parsed structure across queries | direct general algorithm baseline |
| `prepared_cm_factorized` | The same BNet AST through `CMIRBuilder` variable/constant/operator nodes, then `compile_flat` and `FactorizedCountPlan.from_cm_node`; retain prepared equation roots | candidate ingress/representation effect |
| `explicit_packed_cm` | Materialize explicit CM truth data from the same prepared equality roots where the guarded width permits; select unclamped roots and apply clamp masks | explicit representation control, exponential limits retained |
| `biodivine_aeon` | Existing AEON 1.4.2; BNet parse, `infer_valid_graph`, symbolic fixed points; construct perturbed graph or documented equivalent restrictions | symbolic comparator |
| `cadical195_enumeration` | Existing native CaDiCaL 1.9.5 through local `python-sat==1.8.dev20`; `native_fixed_points` | bounded exact enumeration/control, not specialized #SAT |
| `cryptominisat` | Parsimonious `encode_fixed_points` CNF, `run_sat_v2`; only SAT decision and checked witness | native SAT control |
| `d4`, `ganak` | The same parsimonious CNF; `run_exact_counter_v2` with explicit hash-pinned executable | specialized exact-count controls |

The raw and prepared factorized arms must have identical variable ordering, operator semantics, component grouping, numeric representation, cache size and backend. Raw BNet compilation must support constants directly in FlatProgram loads; do not introduce fake unconstrained variables or force raw compilation through CM merely to reuse a convenience translator. The `cm_exprlib` expression family does not expose a constant class; this is why the direct path should target FlatProgram explicitly. `CMIRBuilder` supports real constants.

Do not mistake prepared CM IR for a materialized explicit CM. Record both representations separately. If canonicalization results in byte-equivalent normalized flat programs, the downstream warm evaluation algorithm has no isolated representation difference; any session difference must be attributed to charged construction, preparation or state reuse. An ingress cost difference is not an algorithmic complexity theorem.

CNF gate clauses are bidirectional definitions. Every satisfying biological assignment has exactly one auxiliary extension, so full d4/Ganak count equals original state count. The local tests check this per assignment, not only aggregate equality. Selector-based future encodings need the same proof and tests. Keep model counters on plain unweighted exact CNF; independent-support hints must be stripped or independently validated. New projected contracts use `c p show` explicitly and preserve empty projection; the new run_projected_ganak_v2 wrapper passes local native hidden-multiplicity and empty-projection controls. Projected performance remains unpaired and requires its own matched corpus experiment.

## Sessions, timing and memory

Each timed worker starts from original BNet bytes and an immutable query schedule. Import/runtime startup is measured as supervisor overhead separately; report total caller-observed wall time as well. At each q, execute three repeated sessions in a balanced seeded arm order, one worker at a time, same CPU affinity, no concurrent test load. Repetitions estimate measurement noise, not independent datasets. The worker owns all caches; cold sessions must not inherit warmed state from an earlier arm or model.

Record nonoverlapping cold construction (read/parse/build), preparation (compilation, preprocessing, cache admission), warm query wall times individually, and total session time. Total includes every model-specific cost, all queries, serialization and requested witness validation, including companion witness production. If an AEON graph or CNF must be rebuilt for each clamp, charge that rebuild to each query and expose it as a subphase. Rebuilding only the raw arm while reusing CM preparation would be an invalid attribution comparison. Provide both reusable and forced-rebuild versions of both arms.

Measure peak memory and CPU across the **entire worker process tree**; native counter child usage is mandatory. Windows and Linux measurements are separate environment strata. Do not compare parent-only Python RSS against child-inclusive native solver RSS. Polling RSS is a sampled lower bound unless supported by cgroup/OS peak accounting; label the scope and sampling interval. Record native defaults, preprocessing flags, threads, binary hash, package versions, CPU, affinity and memory limits. An executable name or source revision alone is insufficient binary identity.

Use `cmbench.benchmark_contracts.validate_result` for future row admission. Every row requires mechanism-attribution fields (representation, algorithm, backend, preprocessing, category, explicit ablation identity), model/schedule/source hashes, cluster, partition, q, repetition, complete timing/memory scope, outputs/witness provenance or an explicit failure. This is structural validation, not proof that a claimed effect was established; separately verify referenced ablation/evidence hashes. Historical `bnet_cm_scalar` is rejected by this schema. Timeout/unavailable/unsupported/parse-error/invalid-witness/count-mismatch/resource-limit/backend-error are distinct outcomes. Never serialize failure as zero models.

## Attribution ablations

1. **Representation/ingress:** raw versus CM-prepared equality roots with exactly the same factorized implementation and backend. Match plan topology; hash normalized IR and investigate any differences.
2. **Preprocessing:** disable/enable matched canonicalization, common-subexpression sharing, component grouping and cache admission in *both* ingress arms. If a gain follows preprocessing equally in raw form, classify it as algorithmically general.
3. **Algorithm:** under each ingress compare guarded packed evaluation, factorized evaluation, and a separately named bucket-count algorithm when supported. Changing both ingress and algorithm cannot isolate CM.
4. **Backend:** feed an identical normalized plan/CNF to each backend. AEON versus scalar and d4 versus Ganak remain comparator-only pairs.
5. **Reuse:** cold-rebuild versus retained preparation at q1/q8/q64 for both raw and CM arms. Include break-even query count using measured preparation differences; report no crossing if q64 still does not amortize.

Predeclare one primary candidate/baseline pair, primary q64 total-session cost, and family weighting. Secondary q and ablations are exploratory unless multiplicity is handled in the frozen analysis plan. Full diagnostic rows remain available for all arms, not only a winning subset.

## Falsifiable gates and local execution order

Correctness is a hard gate: every feasible exact arm must agree per query and each SAT witness must satisfy the original perturbed BNet. A mismatch stops that arm and invalidates its timing scoreboard until resolved. Independent auxiliary-extension tests, free-axis tests, empty projections, contradictions, constants and clamp/condition differences must pass. These controls already pass for the new small-model implementation; the future raw/CM translators still need the same tests.

For an eligible held-out population, require **candidate total-session cost / baseline <= 0.95 and the upper endpoint of a two-sided 95% cluster confidence interval strictly below 1.0**. Resample whole ancestry clusters after averaging repeated measurements within instance and clustering variants. Report family-equal and workload-weighted estimands, per-instance ratios, leave-one-family-out sensitivity and size/width strata. Do not issue an acceptance decision if too few independent families, unverified ancestry, adaptive model selection, or censoring makes that interval uninformative. The current three closed heldout-candidates are insufficient for a strong population claim; the historical reports do not pass this new gate by reanalysis.

Timeouts are right-censored. Keep completed/failed totals, lower bounds, and a common-budget success/time score. Never substitute the time limit as a completed time or omit censored families to claim a general win. A complete-pair analysis is a labeled secondary sensitivity. No-go for a CM-specific claim if the matched raw arm reproduces the gain, if charged CM preparation erases the total-session advantage through q64, if correctness differs, or if memory/timeout regressions offset the predeclared objective. These outcomes do not refute all possible CM uses.

Execution stages: (1) preserve this audit and implement the raw/CM equation-root translators and result-emitting session runner locally; (2) exhaustively compare tiny synthetic cases and all feasible small closed-model perturbations; (3) run a single-repetition local development pilot under a 15-minute total wall budget, 10-second per-session deadline and 1-GiB process-tree cap; (4) inspect admission coverage, freeze actual source/binary/input/query manifests, and then run the predeclared local three-repetition matrix within a separately recorded feasible wall budget. Budget exhaustion is an explicit stop with incomplete rows. No large/paid plan follows from the present correctness results alone. Only after local correctness **and performance** gates may a later task prepare a concrete hash-bound paid-compute plan and quote for explicit approval.
