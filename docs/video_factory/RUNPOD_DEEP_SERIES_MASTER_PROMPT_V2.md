## What v2 corrects

Version 2 preserves the useful production rules in v1 but replaces its generic
44-episode outline with an audited 51-episode curriculum and an authoritative
episode content bible.

- Evidence literacy begins with `conceptual-vs-measured`, before viewers see
  conceptual diagrams that could be mistaken for measurements.
- CM-IR identity and persistence are taught before execution variants.
- Packed truth vectors are distinguished from CSE-flat and flat instruction
  lowering rather than being treated as the same optimization.
- `instruction-operations-memory` follows the AST/CSE/CSE-flat/CM-IR mechanism
  episodes, so instructions, primitive operations, storage, and memory traffic
  can be separated on an already-familiar example.
- `no-fastest-chart` follows boundary and ratio literacy instead of preceding
  the concepts needed to understand it.
- The CRSE arc reflects the current source program: the initial matrix/graph/
  fused/retrieval result is explicit, C9-C11 has its own retained-negative
  routing episode, C12-C16 includes the corrected Linux v2 confirmation,
  C17-C20 separates dispatch/transfer/policy/compilation evidence, C21-C22
  separates the task-matched method table from implementation readiness, C23
  isolates fresh-source transfer and its non-promotion limits, and D10 and
  E1-E2 retain their own task boundaries.
- Every episode owns a distinct lesson, names exclusions and prerequisites,
  uses a stable worked example, and has episode-specific teaching beats, visual
  spines, dialogue anchors, misconceptions, caveats, and source/claim IDs.
- The script/storyboard package must receive explicit content approval before
  any broad production batch can be proposed for execution.

## Important execution distinction

The current CM RunPod package is a deterministic render worker. It consumes
immutable jobs and creates hash-bound media. It does not understand this prose
prompt and must not invent scripts, claims, storyboards, or visual direction.

Give this prompt to a coding/production agent with the CM workspace. The agent
may develop all 51 episodes in one resumable invocation, but must author and
validate the content locally first. Only content-approved immutable rendering
inputs may later be placed in an exactly authorized RunPod batch.

The historical `cm-video-proof3-cpu-remote-v1` through `v4` permissions are
consumed. The prior general $5 allowance is not authorization for this series.

SCRIPT AND DIALOGUE CONTRACT

Each script must realize the bible's episode-specific thesis, ownership,
exclusions, teaching beats, visual spine, exact dialogue anchors, retrieval
check, misconception repair, caveats, and closing takeaway. It must include:

1. Hook and promise.
2. Prerequisites and a plain definition before acronyms.
3. Concrete worked example whose visible state changes during narration.
4. Mechanism, including why each transformation occurs.
5. Matched contrast with the nearest confusing concept.
6. Boundary: what the lesson does not establish.
7. Evidence panel when retained evidence exists, otherwise a visible
   conceptual label.
8. Retrieval check with a pause before the answer.
9. Misconception repair.
10. Recap and bridge without a universal superiority claim.

Apply every global dialogue rule in the bible. In particular, each explanatory
cue must cause or interpret a visible change. A reviewer must be able to name
what changed because of the cue. Use short sentences near dense diagrams; put
essential meaning in narration/captions, not color alone; define acronyms on
first use; and do not invent an expansion for CRSE.

Run and record three passes for every script: conceptual completeness,
script-to-visual alignment, and evidence/claim audit. A script cannot be marked
validated while it contains `show boxes`, `add diagram later`, unsupported
facts, unresolved claims, or dialogue that merely reads labels.

VISUAL DIRECTION

construction, stable visual identities, and visible evidence status. Retain
the flagship's useful chapter, boundary, claim/source, matrix, DAG, and ratio
language while increasing explanatory density.

A passive row of three boxes is not an explanation. Three aligned entities are
allowed only when they contain actual lesson information, their relationship
is explicit through shared elements/arrows/axes/transformed values, the scene
progresses through input-transformation-consequence, narration describes the
change, and a concrete example or evidence panel supplies meaning.

- Normally use 55-85 percent of the safe teaching area once a diagram settles.
- Use meaningful visual beats every 3-8 seconds and a changed visual state or
  composition every 8-20 seconds.
- Do not hold a static slide over 20 seconds.
- Progressively construct expressions, tables, graphs, traces, and evidence.
- Every episode needs a worked example, mechanism view, boundary/contrast view,
  retrieval interaction, and recap map.

  need at least three and a chapter roadmap.

  contract, never a center crop of a dense diagram.
