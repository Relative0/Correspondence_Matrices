### New findings from this review

**R1 — identity-basis corpus fields are generation-time values (low /
informational; resolved via lineage, docs clarification recommended).**
Independent recomputation from `expression_v2` disagreed with
`identity_dag_nodes` on 73/192 records (67 tree, 6 shared; small deltas,
e.g. 19→18). Root cause: v2 serialization deduplicates structurally equal
subtrees (e.g. two `Var(3)` leaves), so the archived document cannot
reproduce the *generated* object's identity DAG; `unfolding_factor_identity`
and `operator_mix_identity` share the basis. Lineage check: regenerating
every formula from its recorded seed with the driver's generator reproduced
**all** recorded fields and structural hashes 192/192 — the fields are
exactly derivable from recorded data, just not from the serialized
expression alone. Impact audit: every admission rule and every results
statistic uses structure-determined fields (structural nodes, unfolded
occurrences, sharing factor, structural operator mix) — all verified
matching post-serde; the measurement rows carry only structure-determined
fields. No statistic or claim changes. Recommended (future pass, one line):
document the identity-basis fields as pre-serialization properties
recomputable via seed.

**R2 — foreign/twin identity divergence can duplicate lowered slots
(informational; pre-existing behavior).** The review's "subtle case": after
`b.negate(C)` adopts foreign `C`, an internal build of the same structure
returns the twin `T` (distinct object, equal key). A root reaching the
structure through both identities lowers it twice in id-memoized
`compile_flat` (measured: 2 XOR ops for the shared subterm). Packed
semantics and canonical keys are exact, and the pre-compact-key builder had
*identical* behavior — the foreign child never joined the receiving
builder's intern table historically either, so an internal copy was a
separate object then too. Retention via `_foreign_keepalive` is intended
(id stability) and bounded by builder lifetime; per-call persistent builders
discard it. Production exposure is narrow: the persistent cache returns one
object per digest, so mixed identities need mid-compile eviction or
deliberate cross-builder mixing. Verdict: harmless, documented "local twin"
model not violated (twins are lookup-registration devices; args identity was
never promised), no regression vs history.
