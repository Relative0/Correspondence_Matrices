# Independent audit verdict: CM folding P1–P13

18 September 2026. Ratios compare the named numerator and denominator; less than one is faster. This is an audit of the supplied evidence, not a new preregistered benchmark campaign.

**Verdict: retain the folding mechanism, but do not proceed directly to the proposed telemetry-only C/Cython P14A. Run a measurement-repair and stronger-baseline Python experiment first.** The evidence demonstrates a useful way to avoid symbolic work on selected, deliberately fold-rich DAGs. It does not establish a generally faster compiler, a natural-workload folding benefit, CM-specific superiority, or that CPython pair observation is the only important remaining cost.

Five findings change the interpretation.

1. **The P8–P13 outer source-pipeline timer includes correctness/reporting work.** P13 calls `compile_once` and stops its timer only after that function has converted ANF to an exhaustive truth vector, computed a digest, summarized the result, and returned. The nested compiler timer stops before those operations. Consequently the reported endpoint differs from the preregistered construction-through-lowering endpoint. Reconstructing each raw observation as `source_build_ns + compiler_ns`, then taking case medians, changes P13's case-balanced ratio from **1.01646 to 1.05209**. This reconstruction excludes the wrapper residual; it is not a replacement for a cleanly delimited rerun. The corresponding case-bootstrap interval is **[0.96274, 1.12150]**. No primary crossover is established.

2. **Both timed ANF kernels retain substantial diagnostic overhead.** The shared kernel counts work and repeatedly scans polynomial monomials to track maximum degree, even when `collect_stats=False`. That flag disables selector reporting, not all ANF instrumentation. Direct also clones/reinterns an already freshly constructed source DAG. In three fresh-process exploratory Windows runs, removing instrumentation reduced direct time by about 21%; eliminating its redundant clone reduced the remaining time by about 30%. Apply these improvements symmetrically where applicable before attributing the gap mainly to telemetry.

3. **The dispatcher is tied to source representation.** It requires five distinct interned binary shells on one unordered child pair. With only AND/OR/XOR and canonical commutative interning, a pair has at most three such shells. Canonicalizing operand order changed all five Gate-P annotation decisions to bypass. This exposes a policy limitation, not a disproof of folding: always-P6 still reduced total pair products from **17,087 to 758** on the canonicalized 36 cases. The simple Python canonicalization implementation did not itself win runtime in our diagnostic.

4. **A better exact Python implementation remains available.** Two inexpensive necessary-condition bounds can bypass pair exactification on 19/36 Gate-P and 7/10 natural cases. A combined prototype reuses operand-ID tuples, counts once at dispatch, applies these bounds, and avoids timed diagnostic dictionaries. It preserves the Boolean dispatch decision on 332 recorded recipes plus 2,000 additional DAGs. Separately, 4,040 targeted cases, including 273 positive decisions, and 14,708 integer-boundary checks passed. Exploratory timing showed about **0.949× P13** for the cleaned selected pipeline, but still **1.122× improved direct** case-balanced and **1.034×** by summed medians. This is a promising implementation direction, not a confirmed direct crossover or an attribution to any one micro-optimization.

5. **The positive aggregate result is narrow.** P13 annotates five of 36 Gate-P cases and none of ten natural cones. Its reported workload-weighted ratio of **0.98027** is a ratio of summed case medians for the recorded wrapper endpoint, but removing case `8:11` changes it to **1.03706**. Case-balanced, summed-time, and natural-abstention results answer different questions. Repeated use of Gate-P and overlapping EPFL cones limit generalization.

The positive mechanism survives the audit. Exact four-bit truth-function composition over a common pair of Boolean subexpressions can propagate through locally unprofitable intermediates; a demand-driven lowerer then contracts a profitable ancestor before expanding its descendants. This is ordinary exact Boolean semantics expressed in a CM-compatible representation. A generic optimizer given the same signatures can perform the same contractions. The supplied Gate-A evidence reinforces that conclusion: CM and generic outputs/work agree on all **10,389 admitted rows** checked.

The audit verified all **1,004** package-manifest entries, recovered the public repository at the specified commit, inspected the requested harnesses and benchmark files, reproduced 90 P11–P13 summary comparisons and intervals, and locally reran P13's **332-case invariance** and **1,000-case fuzz** gates successfully. The random fuzz gate annotated only one case; our targeted suite adds positive-branch coverage, which the next protocol should retain. Original inputs and existing workspace changes were preserved.

**The exact next experiment I would run is P14-PY0**, specified in [P14_PREREGISTRATION_DRAFT.md](P14_PREREGISTRATION_DRAFT.md): freeze timing boundaries, remove statistics from both measured kernels, let direct and bypass paths lower their existing DAGs, and compare frozen P13 against the exact bounded Python dispatcher under identical backends. Treat the existing 36+10 cases as development/regression data. Confirm any claim on new circuit-family holdouts and new synthetic families, including representation perturbations. This is more informative than immediately compiling telemetry because it identifies whether there is a meaningful gap left to accelerate against a credible baseline.

If native code follows, share node allocation/interning and the ANF kernel between direct and folded arms, retain an uninstrumented direct arm, and compare telemetry off, telemetry on with forced bypass, and telemetry on with folding. A native-only incremental observer can be an honest engineering improvement; it cannot by itself establish a language-independent algorithmic advantage.
