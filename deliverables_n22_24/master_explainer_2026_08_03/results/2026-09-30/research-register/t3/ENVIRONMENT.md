CUDD is supplied by the pinned dd 0.6.0 manylinux wheel in the unchanged prior package. The installed extension hash is recorded in `ENVIRONMENT.json`; upstream wheel compiler flags are not exposed and are not inferred. The comparator constructs each factor bit as a BDD, combines the products by XOR, performs one explicit automatic sifting pass, freezes the resulting variable order, and exports a signed-edge DAG. The native online kernel memoizes exact residual counts and invalidates that cache on each named update. Factor/BDD construction, reordering, export and native-state loading are charged. This configuration follows the [official dd CUDD interface](https://github.com/tulip-control/dd/blob/v0.6.0/dd/cudd.pyx) and [official reordering documentation](https://github.com/tulip-control/dd/blob/v0.6.0/doc.md). It does not use CUDD floating-point minterm counts.

Packed persistence has a binary scope header and tightly packed truth bits. The C++ kernel constructs it from supplied factors, compacts it after destructive restrictions, and uses popcount with repeated-count caching. Raw-factor persistence packs supplied-width profiles into bytes and uses a native parity pair loop after charged coordinate selection; widths above 64 would use the exact Python fallback. The Draft-3 comparator implements the retained coordinate-sensitive histogram/Walsh identity, with a sparse direct pairing fallback above width 12. It is labeled a historical mathematical path, not an optimized KC package; the original frozen implementation is preserved unchanged in the prior delivery.
