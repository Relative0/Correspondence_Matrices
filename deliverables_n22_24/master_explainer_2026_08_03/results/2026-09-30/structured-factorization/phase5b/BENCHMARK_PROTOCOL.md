# Phase 5B frozen protocol

Registered 2026-09-29 before executing any new benchmark method. Frozen reproduction must pass before tuning/running this campaign. Code repairs for correctness are allowed, must be logged, and invalidate affected runs. No objective tuning is planned: the coefficients below are fixed in advance. Held-out observations may not change them.

This is a maintained-tool, small-instance pilot, not an industrial-scale campaign. Ten generated families each contain training n=6,8; validation n=6,8; held-out n=6,8,10 (70 instances total). Families: clean factorable, partly factorable, redundant cross-links, path/bounded-treewidth, planted random CNF, read-once operators, repeated syntactic modules, aligned carriers, crossing carriers, indecomposable equality controls. All use 1-based original variables with no auxiliary variables in the factorization universe. Exact generator and seeds are in code/make_benchmarks.py and data/benchmark_manifest.json. Public licensed examples, if obtainable, form a separately reported external challenge set; they cannot alter the primary set or decision.

Three replicates use seeds 3101, 3102, 3103. B1 chooses one independently seeded recursive random vtree per replicate. Other methods are deterministic, replicated for timing variation. Run order is shuffled within split with seed 2026092906. Train, then validation, then held-out are executed; algorithm source and manifest hashes are captured before held-out. Evaluation computes semantic factors independently by enumerating satisfying assignments and testing Cartesian projection cardinalities, outside timed algorithms. Only O receives that partition. Non-oracle workers receive CNF, carrier and seed only.

Methods: B0 balanced fixed order; B1 random recursive tree (not uniform over labelled trees); B2 maintained PySDD manager minimization starting B0; B3 syntax components with greedy min-fill order inside components; M1 exposure local search; M2 joint size/residual-work local search; M3 M2 plus soft carrier spans; M4 M2 plus minimized defect-support spans; M5 M2 plus both; O semantic-prime-aligned evaluation control. B2 is the native library procedure; M methods use explicit local rotations and child swaps followed by full recompilation, with all recompilation charged. Their budgets are not identical to B2's internal search; report this limitation. B3 is a modest standard graph baseline, not a state-of-the-art portfolio.

M methods start from B3. Evaluate at most 12 distinct neighboring trees total over at most two greedy rounds, in deterministic serialized order. M1 lexicographically maximizes exposed block count with serialized-tree tie breaking. M2 minimizes log2(1+real SDD element size)+log2(1+sum(2^(block size-1)-1)), where the sum is over exposed nonsingleton blocks. This is a search proxy, not a SAT-runtime prediction. M3 adds the mean normalized excess LCA span of carrier blocks; M4 adds that of support unions U union W; M5 adds both with coefficient one. No carrier hard locks; no hyperedge-to-clique must-links. M4/M5 probe at most three deterministic balanced-tree cuts, shrinking witness support by equality assumptions. Probe/setup/shrink overhead is charged independently in each run.

Primary comparison: M5 versus the better B2/B3 baseline selected using validation geometric-mean total runtime (PAR2 for failures). Freeze selection before held-out. Additional method comparisons are exploratory. Primary runtime includes construction, compilation/recompilation, extraction, probes/support processing, search, exact residual SAT, and carrier partition assembly. Interpreter startup, input parsing, independent evaluation, result serialization and separately marked move diagnostics are excluded equally. All nonsingleton exposed blocks remain residual unless independently certified. Peak process working set includes interpreter/dependencies; one fresh worker per trial avoids accumulated high-water values.

Watchdog: 15 seconds per worker trial; timed-out/error runs are failures, receive PAR2=30 seconds in primary comparisons, and never count as correctness successes. Report censoring and failure counts. Peak memory uses OS process high-water working set where available. Principal performance runs are sequential, with no other project computation deliberately concurrent. No cache/results shared across competitors. Completed trials measure actual wall time; results faster than timer granularity receive no artificial speedup claim.

Primary GO requires zero correctness disagreements, no excess failures relative to selected baseline, paired geometric-mean M5/baseline ratio <=0.90 and a 95% paired instance-bootstrap upper ratio <1 (10,000 draws, seed 2026092907). Use median of three repetitions per instance before pairing/bootstrap; report median/mean/IQR, per-instance wins/losses, family strata and all raw rows. This pilot cannot alone establish industrial improvement even if its numerical criterion passes. A residual-work rescue requires >=25% median paired SAT-call reduction AND >=10% median SAT-wall reduction, with >=5ms median absolute SAT-wall saving per instance; this is registered before data and cannot replace the runtime primary. If neither criterion passes, algorithmic NO-GO for this implementation/campaign.

For every explored local move, record actual SDD-size, exposure, residual-volume changes and compile/extract cost. Measure candidate residual-SAT cost in a separate diagnostic run after primary timing; never feed diagnostic partitions or times back into objective weights. Diagnostic timeouts remain explicit and do not change the frozen campaign. Report Pareto pairs and objective agreement/antagonism descriptively, not as general theorems.

No claim of novel rotations, graph-guided compilation, component decomposition, or incremental SAT. No learned-clause reuse count is inferred from conflicts or runtime. Preserve negative results and review failures.
